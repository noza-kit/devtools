# slidecraft — 実装レポート

## ステータス: 完了(保留中の質問なし)

slidecraft_detail.mdの全機能(モジュールA・B・C)を実装しました。
「Google Slides連携は不要、python-pptxのみで構いません」とのご回答通り、
PPTX出力のみに絞っています。

## 完了した機能

### モジュールA: パーサー & スライド生成
- BeautifulSoupによるHTML解析 — `<section class="slide">`ごとに
  タイトル・本文・画像・ノートを抽出
- レイアウト自動判定 — 画像の有無に応じてテンプレート内のレイアウト名
  (`Two Content`/`Title and Content`等)をキーワードマッチで検索し、
  見つからなければ「タイトル+その他プレースホルダーが1つ以上あるレイアウト」
  にフォールバック
- リッチテキスト装飾の再現 — `<strong>`/`<em>`で囲まれた部分のみを
  python-pptxの`run.font.bold`/`italic`で太字/斜体化(段落全体ではなく
  該当ランのみ)

### モジュールB: テンプレート管理
- `--template`でのマスターテンプレート適用(python-pptxの`Presentation(path)`で
  フォント・背景・プレースホルダー位置を継承)
- デフォルトテンプレート — python-pptx自体が内蔵しているデフォルト
  テンプレート(白背景+標準フォント)をそのまま利用する設計にしました。
  独自にもう1つデフォルトpptxを同梱するのは冗長と判断したためです
  (READMEに理由を明記)。

### モジュールC: LLM連携サポート
- `slidecraft --get-prompt` — 期待するHTML構造を説明するシステム
  プロンプトを標準出力に出力(`slidecraft/prompt.py`)

## テスト

`pytest slidecraft/tests` — **35件全てパス**。実際のLLM APIは一切使用
しません(slidecraft自体はプロンプトを生成するだけで、LLM呼び出しは
ユーザーが手動で行う設計のため、モック化の必要すらありませんでした)。

## 発生した問題・設計判断

1. **重大なバグ(実装中に発見・修正済み)**: 画像とテキストが両方あるスライド
   で、テキストを書き込んだプレースホルダーが誤って削除され、空の
   プレースホルダーが残ってしまう不具合がありました。原因は
   `slide.placeholders`がアクセスの度に新しいPythonラッパーオブジェクトを
   返す実装になっているため、「このプレースホルダーはテキスト用として
   除外する」という判定を`is`(オブジェクト同一性)で行うと常に不一致に
   なってしまうことでした。`idx`(プレースホルダー番号)による比較に
   修正し、回帰テスト(`test_text_placeholder_survives_alongside_image`)を
   追加しています。スモークテストで実際にPPTXを生成して中身を検証した
   ことで発見できました。
2. **`pptx.shapes.Picture`のインポートパス**: 当初`from pptx.shapes import
   Picture`としていましたが、実際は`pptx.shapes.picture`サブモジュールに
   あり、修正しました。
3. **レイアウト自動判定の精度**: 「一任します」とのご回答に基づき、
   PowerPoint標準のレイアウト名(`Two Content`等)による文字列マッチ+
   フォールバックという現実的な実装にしました。完全に独自命名の
   テンプレートでは最適なレイアウトが選ばれない可能性がある点をREADMEの
   「Known limitations」に明記しています。
4. **プロンプト文面**: 「一任します」とのご回答に基づき、こちらで
   作成しました(`slidecraft/prompt.py`)。
