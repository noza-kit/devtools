# gazemouse — 実装レポート

## ステータス: 完了(保留中の質問なし)

gazemouse_detail.mdの全機能(モジュールA〜D)を実装しました。カメラ・
モデルファイル無しでは実機検証ができないという性質上、**アルゴリズム層は
実際のロジックとして完全にテストし、カメラ/モデル/実際のマウス制御は
明確に「未検証」として切り分ける**という設計方針で進めました。

## 重要な発見: MediaPipeのAPI変更

実装開始時にMediaPipeの実際のバージョン(1.0.0)を確認したところ、
仕様書が前提としている`mp.solutions.face_mesh`/`mp.solutions.hands`/
`mp.solutions.pose`という「レガシーSolutions API」が**完全に削除**されて
いることが判明しました。現在は`mediapipe.tasks.python.vision`配下の
`FaceLandmarker`/`HandLandmarker`/`PoseLandmarker`という新しい「Tasks
API」に置き換わっており、これらは別途モデルファイル(`.task`)のダウン
ロードが必要です。本実装はTasks APIを前提に作り直し、READMEに
モデルファイルの入手先(Google公式)を明記しました。この変更に気づかず
旧APIのまま実装していたら、実行時に即座にエラーになっていたはずです。

## 完了した機能

### モジュールA: 視線ポインティングとジッター対策
- 両目の虹彩中心(MediaPipe Face Mesh標準インデックス468, 473)の平均位置
  を取得
- EMA(指数移動平均)によるスムージング: `Smooth = alpha*Current +
  (1-alpha)*Previous`(仕様書の数式そのまま実装)
- 4隅キャリブレーション: 画面四隅を見た時の虹彩位置バウンディングボックス
  から線形(クランプ付き)マッピング

### モジュールB: 2秒閉眼スクリーンショット
- 標準EAR(Eye Aspect Ratio)公式による開閉眼判定
- 「両目または片目」の仕様に対応するため、左右のEARの**小さい方**
  (より閉じている方)を判定に使用 — 意図的なウィンクも両目closeも
  同じロジックでトリガー
- 2秒間の継続閉眼のみをトリガーとし、通常のまばたき(0.1〜0.3秒)は無視
- トリガー後は目が開くまで再発火しない(1回のみ)
- **snapclipとの連携**: `snapclip.capture.take_stack_screenshot`を
  直接importして呼び出し。snapclipが未インストールの場合は警告を出して
  この機能のみ無効化(ハードな依存にしない設計)

### モジュールC: 首振りスクロール
- 顎-額間の垂直距離(正規化座標)を頭部ピッチの代理指標として使用
  (Pose推定モデルを追加ロードせずFace Meshのみで完結させるため)
- セッション開始時のピッチをベースラインとして自動キャリブレーション
- デッドゾーン付きでベースラインからの偏差をスクロール量に変換
- **視線とスクロールが完全に独立**していることをテストで保証
  (仕様書が指摘する「見下ろすとカーソルも一緒に下がる」問題を回避)

### モジュールD: 手のジェスチャー・クリック
- 手首から各指先/PIP関節までの距離比較による開閉判定(4本指中3本以上
  伸展で「開」)
- 「パー→グー」の立ち上がりエッジをマウスの`mouse_down`に、
  「グー→パー」の立ち下がりエッジを`mouse_up`にマッピング。単純な
  クリックとドラッグを、物理マウスボタンと全く同じ仕組み(押しっぱなし
  =ドラッグ)で自然に両立させる設計にしました(仕様書には「クリックは
  エッジで1回発火、長押しはドラッグ」と別々に書かれていましたが、
  実装上は同じdown/upメカニズムで両方を満たせると判断しました)

### パフォーマンス・省エネ設計
- FPS制限(デフォルト17fps、仕様の15〜20fpsの範囲内)
- **セーフティ機能**:
  - 顔がフレームから消えると自動的に無効化(顔が戻ると自動復帰)
  - Escキーによる即時キルスイッチ(顔が戻っても自動復帰しない — 明示的な
    `re_enable`が必要)
  - ご要望に基づき追加: 明示的なON/OFFトグルホットキー(デフォルト
    `Ctrl+Alt+G`)

## テスト

`pytest gazemouse/tests` — **63件全てパス**。

**実際のロジックとして完全に検証した部分**: EMAスムージング、
キャリブレーション(境界ボックス計算+線形マッピング+クランプ)、
EAR計算+2秒閉眼検出ステートマシン、手の開閉判定+クリック/ドラッグ/
リリースのエッジ検出、頭部ピッチ推定+スクロール変換、セーフティ
(顔ロスト/キルスイッチ/トグルの組み合わせ)、そして`GazeMouseSession`
による全体の統合ロジック(合成ランドマークデータを使った実際のパイプライン
テスト)。カメラは一切不要な、純粋な入力→出力ロジックとして設計・
テストしています。

**モック化/未検証の部分(この環境ではカメラが無いため、summaryへの記載
指示に基づき明記します)**:
- **実際のカメラ映像・MediaPipe推論**: `MediaPipeLandmarkSource`は
  実際にインストールされているMediaPipe Tasks APIのメソッドシグネチャ
  との整合性は確認済み(`FaceLandmarkerOptions`/`HandLandmarkerOptions`/
  `BaseOptions`等の引数を実際にinspectして確認)ですが、実際のカメラ
  映像に対する推論は一度も実行していません。モデルファイル
  (`.task`)のダウンロードも行っていません。
- **虹彩・EAR・指のランドマークインデックス**: MediaPipeコミュニティで
  広く使われている標準的なインデックス値を採用していますが、実際の顔・
  手に対する精度検証はできていません。
- **実際のマウス制御(pyautogui)**: `PyAutoGuiMouseController`の実際の
  OS操作(カーソル移動・クリック・スクロール)は未検証です。
- **`cli.py`の`calibrate`/`start`コマンド本体**: 設定ファイル未検出等の
  エラーパスのみテスト対象で、実際のカメラを使った対話フロー自体は
  未検証です。

## 発生した問題・設計判断

1. **MediaPipe APIの破壊的変更**(上記「重要な発見」参照)— 実装前に
   実際のインストール済みバージョンを確認したことで発覚し、Tasks API
   ベースで設計しました。
2. **クリック/ドラッグの実装方式**: 仕様書の記述を「オープン→クローズの
   エッジでmouse_down、クローズ→オープンのエッジでmouse_up」という
   物理マウスボタンと同じ仕組みに単純化しました。これによりクリックと
   ドラッグを同じコードパスで自然に処理できます。
3. **首振りスクロールの実装**: MediaPipe Poseモデルを別途ロードせず、
   既にロード済みのFace Meshランドマーク(顎・額)だけで頭部ピッチを
   近似する設計にしました。厳密な角度(度数)ではなく相対的な変位量です
   が、スクロールの用途には十分と判断しています。
4. **FPS制限の初期化バグ(実装中に発見・修正済み)**: `_last_frame_time`
   の初期値を`0.0`にしていたところ、`now_fn`が`0.0`から始まるテスト
   (またはモノトニッククロックが偶然0付近から始まる実環境)で最初の
   フレームが処理されない不具合がありました。`float("-inf")`に変更し、
   常に最初の呼び出しが処理されるよう修正しています。
