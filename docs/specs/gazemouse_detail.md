次世代ハンズフリー・マウス＆アクション制御ツール（仮: gazemouse）完全仕様書1. コアコンセプト完全ハンズフリーの操作性: 一般的なWebカメラとPython（MediaPipe等）を用い、「視線（アイ・トラッキング）」によるポインティングと、「身体のジェスチャー」によるアクションを組み合わせた次世代のデスクトップ操作環境。Midas touch（誤爆）の完璧な回避: 「見つめているだけでは操作が起きない（移動専用）」という原則を貫き、クリックやスクロール、スクリーンショットなどのアクションは専用の物理・生体ジェスチャーに割り当てる。エコシステムとの連携: 撮影したスクリーンショットは、これまで設計した snapclip のコアロジックや保存先に直接連動させる。2. 操作マッピング定義（入出力の設計）操作対象ユーザーの動き / ジェスチャー判定技術・ライブラリ動作内容ポインタ移動画面を見る方向を動かすMediaPipe Face Mesh (Iris)視線のベクトルを算出し、スムージング（EMA）をかけてマウスカーソルを追従させる。左クリック右手をギュッと握る（グーの形にする）MediaPipe Hands視線で狙いを定めた状態で、右手を握ると「マウスクリック（左）」を発火。スクリーンショット両目または片目を「2秒間連続して閉じる」MediaPipe Face Mesh (Eye Aspect Ratio)瞬きではなく「意識的な2秒間の閉眼」を検知し、瞬時に画面をキャプチャして保存＆クリップボードへ格納。スクロール首を上下に傾ける（ピッチ方向の傾き）MediaPipe Pose / Face Mesh視線を固定したまま顔全体（あご）を上下に向けると、その角度と速度に応じて画面をスムーズにスクロール。3. 機能詳細と技術仕様モジュールA: 視線ポインティングとジッター対策 (Gaze Engine)アプローチ: Webカメラの映像から両目の虹彩（Iris）の中心位置を検知し、画面上のXY座標にマッピング。ローパスフィルター (EMA: 指数移動平均):人間の黒目は微細に震えるため、フィルターを挟まないままだとカーソルが激しく暴れる。Smooth_X = alpha * Current_X + (1 - alpha) * Previous_X の計算式を挟み、カーソルが「ヌルッと吸い付くように」移動するチューニングを行う。モジュールB: 2秒閉眼スクリーンショット (Blink Trigger)誤検知防止（生理的まばたきとの分離）:通常のまばたき（0.1秒〜0.3秒）は完全に無視する。「目を閉じた状態が 2.0 秒以上継続したこと」をタイマーで厳密に監視。2秒に達した瞬間、視覚的・聴覚的フィードバック（画面が一度わずかにフラッシュする、または小さな通知音）を鳴らし、裏側で snapclip のキャプチャ処理を実行する。モジュールC: 首振りスクロール (Head-Tilt Scroll)なぜ「視線」ではなく「首の傾き」でスクロールするか:視線だけでスクロールさせようとすると、「下を見ようとして視線を動かすと、カーソル自体が画面の下に移動してしまう」という矛盾（コントロールとビューの競合）が生じる。そのため、「カーソルは視線で維持しつつ、スクロールは顔全体の上下（あごを引く・上げる）」という分離設計にすることで、直感的なスクロールを実現する。モジュールD: 手のジェスチャー・クリック (Hand Click)右手のグリッド認識:画面の邪魔にならない位置に手を置き、指の関節座標から「開いている（パー）」か「握っている（グー）」かを高速判定。「パー → グー」に変化した瞬間（立ち上がりエッジ）に1回クリック判定を送信する。長押し中はドラッグ＆ドロップ状態として扱う。4. パフォーマンス・省エネ設計フレームレートの間引き (FPS Limiting):リアルタイム処理によるCPU/GPUの爆熱化を防ぐため、カメラ映像の解析は常に60fpsで行うのではなく、15fps〜20fpsに間引いて処理する（マウス操作において人間の知覚や追従性として十分な速度を維持しつつ、負荷を大幅に削減）。スリープ＆セーフティスイッチ:カメラから顔が消えた場合や、特定のホットキー（例: Esc キー）を押した瞬間に、自動で gazemouse の制御をオフにして通常のマウス操作へ完全に明け渡すフェイルセーフ機能を必ず実装する
